**Disabling six more weak TLS cipher suites by default in the API Management service module — held up by changes to CI files that every module shares.**

On 1 November 2025 ronaldbosma asked whether cipher suites listed as weak should be disabled in the module (https://github.com/Azure/bicep-registry-modules/issues/6167). The next day AlexanderSehr answered that the existing list could be expanded: "We'd just need to mark it as as a breaking change and call it out as such in the changelog" (https://github.com/Azure/bicep-registry-modules/issues/6167#issuecomment-3478056843).

On 10 June 2026 abhishekaryams opened #7146 (https://github.com/Azure/bicep-registry-modules/pull/7146). Its first commit adds six entries to the default of the `customProperties` parameter in `main.bicep`, among them `TLS_RSA_WITH_AES_256_GCM_SHA384` (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/b8a69df338b3843a7ba1d7c901d3e72de367d1d0). A second commit added `skipPassedRulesReport: true` to `.github/workflows/avm.template.module.yml`, the workflow template every module's pipeline runs (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/8195089d59525e325e99e4ae308b50fea6e1c075). On 13 June 2026 eriqua asked "is this intended/needed? Please remove otherwise as it would impact all the modules" and requested changes because the changelog was missing (https://github.com/Azure/bicep-registry-modules/pull/7146#discussion_r3408199937, https://github.com/Azure/bicep-registry-modules/pull/7146#pullrequestreview-4491660896). A changelog entry followed the next day (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/b5c99e3594a714b4fd25a98430d0e50e9266064f).

On 15 July 2026 the author replied that the run was failing "due to the size" (https://github.com/Azure/bicep-registry-modules/pull/7146#discussion_r3584655966). The next day a commit removed the `skipPassedRulesReport` input from the workflow template (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/3c81f968721aa128955b2112c549d54795fadfe2), and two commits made the shared rule-check and test actions truncate their job summary, with the code comment `# GitHub step summary limit is 1024KB total. Use 900KB to leave headroom for other steps.` (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/1cf226a8fbedbebcd226b23b062b8e0712b3a2ec, https://github.com/Azure/bicep-registry-modules/pull/7146/commits/1b26258092cca35ba124ba4549705b28061d162e). eriqua replied "That will also impact all modules" and asked for an issue so a CI exception could be planned (https://github.com/Azure/bicep-registry-modules/pull/7146#discussion_r3594634118). On 27 July 2026 the changelog entry was rewritten to name the six suites (https://github.com/Azure/bicep-registry-modules/pull/7146/commits/94574d761f8b51c92ff01673ccc76812495b08a6). On 5 September 2026 the author opened #7331 and asked to be told "once that is fixed so that we will able to close this" (https://github.com/Azure/bicep-registry-modules/pull/7146#discussion_r3941212615); AlexanderSehr pinged eriqua on 18 September 2026 (https://github.com/Azure/bicep-registry-modules/pull/7146#discussion_r4047081258).
